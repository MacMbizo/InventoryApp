Kitchen Inventory — UI/UX Review & Redesign

25 October 2026· WPF / .NET 8 desktop· Audience: non-technical school kitchen staff· Method: source review of all 15 XAML views + ui-ux-pro-max skill data

Verdict: the app is functionally strong but visually and verbally unfinished. There is no design system at all — App.xaml declares zero colours, styles or fonts, so every control renders as raw Windows chrome. The deeper problem is not looks: it is that the interface speaks in the language of its database (“Adjust Stock”, “Audit Trail”, “ItemId”, “Needs Attention only”) and puts 13 equally-weighted buttons in one undifferentiated row. A caretaker who has never used inventory software will not know which button to press, and one stray click on Delete — sitting directly beside Add — silently removes a record with no confirmation.

Good news: the underlying architecture is already the thing that makes a redesign cheap. Strong MVVM separation, a complete AutomationId on every actionable control, a documented UI/UX spec, and a 13-test FlaUI suite mean a visual overhaul can be delivered without touching business logic — and the UI suite will catch regressions.

Design tokens to add to App.xaml

This is the single highest-leverage change, and it is small. Today App.xaml contains only two converters. Everything below goes into one Themes/Tokens.xaml merged dictionary, so the whole app can be restyled — or a dark theme added later — in one file. The skill's guidance for this stack is explicit: use a resource dictionary in App.xaml, prefer implicit styles over per-element setters, and prefer StaticResource over the DynamicResource currently used for the side-panel background.

Findings and fixes, in priority order

Critical Deleting an item is instant and irreversible

Delete sits immediately to the right of Add and fires on click with no confirmation. DeleteSelectedAsync removes the row from the list and the database in one step. For the user this is the worst possible failure: a recording error they cannot take back.

Fix: add a confirmation dialog that restates the item, its stock and the date (mockup above), put the safe choice first, and word the buttons “Keep item” / “Remove item”. Because Gate 1 just made deletes soft, also add Undo on the following confirmation — a 10-second “Sugar was removed · Undo” strip. Keep the keyboard shortcut off the bare Delete key.

ItemsViewModel.cs:524 · MainWindow.xaml:43

Critical The interface speaks database, not kitchen

“Consume Stock”, “Adjust Stock”, “Audit Trail”, “Recent Movements”, “Per-item movements”, “Needs Attention only”, and a table column literally headed ItemId. Every one of these is a translation step a non-technical user has to perform before acting. “Adjust” in particular sounds like a minor tweak; it is in fact the destructive operation that overwrites a stock count.

Fix: a label pass over the whole UI — see the before/after list above. Two rules: (1) name the real-world event, not the record change; (2) never show a database concept (Id, GUID, “movement”, “entity”). A single resources/Labels.xaml dictionary would let this be reviewed and localised in one place.

MainWindow.xaml:41-91, 216-306 · StockOperationDialog.xaml

High There is no design system at all

App.xaml declares two converters and nothing else. Consequences visible in the code today: two different error reds (#FFCC0000, #DC2626), three ad-hoc ambers, Gray used for help text at ~2.3:1 contrast, a DynamicResource system brush in one place and hard-coded #DDD borders in another, and fifteen views each inventing their own spacing.

Fix: one Themes/Tokens.xaml (colours, spacing, radii, type) plus Themes/Controls.xaml with implicit styles for Button, TextBox, ComboBox, DataGrid, ToolTip. Then strip the inline setters. This is also the prerequisite for every other fix on this page — do it first.

App.xaml (entire file) · MainWindow.xaml:38, 214 · AddItemDialog.xaml:39, 46

High Warnings depend on colour alone

The only signal that something is wrong is a pale amber row background (#FFFDECC8) driven by NeedsAttentionConverter. It has no icon, no text and no legend; it is identical for “expired a month ago” and “expires in six days”; and roughly 1 in 12 men will not see it. The severity that does exist lives in a different tab.

Fix: a Status column with an icon + words + colour (“Expired 12 days ago”, “Running low”, “Expires in 3 days”, “OK”), and carry that same status into the right-hand cards. Keep the row tint as reinforcement, not as the message.

MainWindow.xaml:119-135 · Converters/NeedsAttentionConverter.cs

High Everything is a button, so nothing is a next step

Thirteen buttons, three separators made of margins, no grouping, no primary action, and “Reports” appearing twice (menu and toolbar). The most useful control — stock operations — is disabled until a row is selected, and the only explanation is an reading “Add stock to selected item”. A new user’s first guess is usually wrong.

Fix: one blue primary (“Add item”), the three everyday stock actions in a labelled row that explains why they are disabled when they are, and everything occasional (“Unit Converter”, “Manage Categories”, “Manage Locations”, “Reports”, “Diagnostics”) behind “More”. That takes the visible count from 13 to 5.

MainWindow.xaml:40-92

High Nothing to see on day one

An empty database renders an empty grey DataGrid with column headers and an empty Alerts tab reading “Low stock, expiring and expired items / Low: 0 Expiring: 0 Expired: 0 Critical: 0”. The user’s first experience of the app is a void, with no hint about what to do.

Fix: the empty state above — one sentence of reassurance, one primary button, one alternative. Add the same treatment to the alerts panel (“Nothing needs your attention right now · You’re all caught up”) and to the search case (“No items match ‘sugar’ · Clear search”), which is different from having no data at all and today looks identical.

High Controls are too small for tired hands

Buttons inherit default WPF metrics (≈22 px tall, 8 px font padding) and items-grid rows are ≈22 px. WCAG 2.2 sets a 24 px minimum target; comfort guidance is 44 px. Several toolbar buttons are also only 4 px apart, which invites mis-clicks — and the neighbour is sometimes Delete.

Fix: 38 px buttons, 44 px rows, 8 px minimum gap between adjacent controls, generous padding inside the dialog buttons (“Keep Sugar” not “Cancel”). The _Cancel / _Add width of 90/120 px in the Add dialog is a reasonable start but should become a shared style.

Medium The window opens smaller than its own content

Default size is 800×480, split 2:1, so the activity panel gets roughly 265 px — but its Alerts GridView hard-codes 80+100+140+180+100 = 600 px of columns. Text is guaranteed to truncate, with a horizontal scrollbar inside a narrow panel. Nothing sets MinWidth/MinHeight, so the user can also shrink it into an unusable state.

Fix: open at 1100×700, set MinWidth="960" MinHeight="600", and replace the fixed-width alert grid with the stacked cards in the mockup — cards reflow in any panel width, grids do not.

MainWindow.xaml:10, 213-249

Medium “Editable grid + separate Save” is a trap

Every column in the items grid is editable inline with UpdateSourceTrigger=PropertyChanged, yet committing needs a separate “Save” button. So a stray keystroke while a row is selected changes a quantity that looks applied but is not — and if the user never presses Save, or navigates away, the edit is silently lost. Meanwhile the status bar says “Ready”, not “unsaved changes”.

Fix: make the grid read-only and route editing through the item dialog (double-click or F2), which is where validation already lives. If inline editing is kept, autosave it, and show a persistent “Unsaved changes” banner with Save/Undo.

MainWindow.xaml:104-118, 157-210

Medium Feedback is quiet and easy to miss

The only feedback channel is a 12 px StatusBar at the bottom of the window — the furthest point from where the user just clicked. There is no busy state on long operations (CSV import, report generation), no success confirmation, and nothing tells the user that the 5-minute background alert refresh has happened.

Fix: inline busy state on the button that was pressed (disabled + spinner), plus a short-lived confirmation near the action (“Sugar’s stock was updated to 12.5 kg”), and keep the status bar for ambient truth like “Everything you change is saved straight away”.

MainWindow.xaml:312-319 · ItemsViewModel status handling

Medium No keyboard shortcuts anywhere

A grep across all fifteen views finds zero InputBindings. The skill’s WPF guidance is to bind gestures to commands rather than handle PreviewKeyDown. Without Ctrl+S the “Save” button becomes a cognitive burden; without Ctrl+F the search box is undiscoverable.

Fix: add Window.InputBindings — Ctrl+N add, Ctrl+F search, Ctrl+S save, F2 edit, F5 refresh — and surface them in the button tooltips. Note the mnemonics already exist in some dialogs (_Item name, _Cancel) but not on the toolbar.

MainWindow.xaml (no InputBindings) · all views

Low Data presented in machine formats

Quantities format as N2 so 10 kg reads “10.00”; expiry dates are yyyy-MM-dd; movement timestamps are UTC with seconds. None of these are wrong, but each one is a small extra step for a reader who thinks in “10 kilos” and “30 November”.

Fix: trailing-zero trimming for quantities (they are already stored at 3 dp), friendly dates (“30 Nov 2026”, “in 6 days”), local time, and no seconds unless expanded. A shared QuantityDisplayConverter keeps it consistent.

MainWindow.xaml:159, 185, 269, 296

Low Dead and duplicated navigation

The Help menu’s “About” item has no Click handler — it does nothing. “Reports” exists both as a top-level menu item and a toolbar button. A top-level “Settings” menu item that opens a window is not the Windows pattern users expect.

Fix: wire or remove About; drop the duplicate Reports entry; and add a small window Icon to both the window and the exe (currently none), which matters for taskbar recognition on a shared school machine.

Suggested sequence

Wave 1 — Safety and words Highest value

The things a user can be hurt by today. Small, testable, no visual risk.

  • Confirm-before-remove dialog (+ Undo strip, now that deletes are soft).
  • Full plain-language pass over buttons, tabs, column headers and messages.
  • Keyboard shortcuts via InputBindings; wire or remove “About”.
  • Set MinWidth/MinHeight and open at 1100×700.

Wave 2 — The design system

One mechanical change that every later change benefits from.

  • Themes/Tokens.xaml + Themes/Controls.xaml, merged in App.xaml.
  • Implicit styles for Button/TextBox/ComboBox/DataGrid/ToolTip; strip inline colours and sizes.
  • 38 px controls, 44 px rows, 8 px radii, consistent 16/24 px padding.
  • Add a Lucide-style SVG icon set for the toolbar and status pills (icons always paired with text).

Wave 3 — Structure and warmth

Make it feel considered rather than assembled.

  • Toolbar regrouped behind one primary action and a “More” menu; filter bar separated.
  • Status column + attention cards replace the cramped alert grid.
  • Empty, no-results and all-clear states.
  • Read-only grid with dialog-based editing, or true autosave with a visible saved indicator.
  • Friendly quantity/date formatting; busy and success feedback.

On “not dreary”: the restraint above is deliberate, but restraint is not the same as grey. The warmth should come from three cheap places — a real colour identity on the one primary action and the status pills, a proper empty state with an illustration, and honest human sentences (“Nothing needs your attention right now. You’re all caught up.”). That reads as calm and cared-for rather than dull. Two things I would not do: no decorative animation (this is a twice-a-day tool on possibly old school hardware), and no emoji as icons — the skill's checklist calls that out explicitly, and it renders inconsistently across Windows versions.

Provenance. Recommendations are grounded in the installed ui-ux-pro-max skill data — ux-guidelines.csv (empty states, confirmation dialogs, colour-only signalling, target size, inline validation, loading feedback, focus states, error placement) and data/stacks/wpf.csv (resource dictionaries over inline values, implicit styles, StaticResource over DynamicResource, AutomationProperties.Name at High severity, InputBindings over PreviewKeyDown). The --design-system query auto-routed to a marketing-landing pattern (hero section, Claymorphism) which does not fit a data-entry desktop tool, so its layout and style suggestions were discarded; only its palette caution — “avoid muted colours and low energy” — was kept. Component metrics follow the project's existing kitchen-inventory-ui-ux-specification.md (Primary Blue #2563EB, 4px spacing base, 8px radius, 4.5:1 contrast, 44px minimum target), which the app has so far not implemented.
